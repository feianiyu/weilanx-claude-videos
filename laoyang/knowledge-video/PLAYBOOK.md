# 做一期深度视频的操作手册（给接手的 AI）

> 读法：先读本页，再按需读 `STANDARD_DEEP_V3.md` / `STANDARD_DEEP_V4.md`（画面和配音）、`STANDARD_RETENTION_SCRIPT.md`（文案）、`STANDARD_REPORT_DIGEST.md`（转述智库报告时）。
> 环境、密钥、机器见 `ENVIRONMENT.md`。出片机细节见 `../mac-render/README.md`。
> 本页每一条规则都来自真实踩过的坑；「过关标准」都能用命令检查。2026-11-12 整理。

## 0. 分工

| 谁 | 做什么 |
|---|---|
| 老杨 | 给素材（文章、转写稿、报告）；**确认文案**；**听片**；**手动发布** |
| 你（AI，云端） | 写文案、做卡片、本地构建检查、推渲染分支、读出片结果、按结果修 |
| Mac 出片机 | 配音（老杨本人声音）、下载素材、渲染、质检、封面、压发布版、写出片报告和初筛 |

**你不做的事：** 不自己配音（没有凭证）；不把片子提交发布台；不在老杨没确认文案前建期或推渲染分支；不替老杨判断配音读得对不对（要他听）。

## 1. 一期的流程

1. **收素材，先写文案，发给老杨确认。** 用 `STANDARD_RETENTION_SCRIPT.md` 的入口卡（处境 / 说不通 / 本质句 / 决策）和六拍（钩、证、约、推、破、落）。转述智库报告时再叠 `STANDARD_REPORT_DIGEST.md`。文案存到项目文档 `选题/EPxx_主题_文案.md`，并把全文发给老杨。
   - 老杨说“数据不需要核实”时，数字按他给的稿子，但你看到口径对不上的地方（例如把“出货量”说成“销售”），要在文案文档的“风险”里写明，并在回复里提一句，不要悄悄改数字。
   - 文案要有：入口卡、全文表（拍 / 句 / 口播）、开环表、相对原稿删了什么、发布信息、风险。
2. **老杨说“确认文案”后才开工。** 期号 = 已有最大号 + 1，目录 `episodes/<日期>_<短题>_v4/`。
3. **复制上一期的 `gen_lines.py` 改写**（最新参考：`2026-11-12_建筑业新文艺复兴_v4`、`2026-11-12_双十一消费趋势_v4`）。它生成 `lines.json`：句子表 `(段, 台词, emo)` + 卡片表 + 元信息。
4. **找一张新底图**（每期必须新图，不重复）：Pexels 原图链接（不带 `?w=`），竖屏裁切后高度要 ≥1962px。横图也行（居中裁切），但原图高度要够。
5. **本地构建检查**（见第 2 节）。
6. **清理并推两处**（见第 4 节）。
7. **等 Mac 出片**，约 5 分钟接单、几分钟到十几分钟渲染。读 `待审/<期>/初筛.md` → 需要时读 `出片报告.md` 和联系表。
8. **把结果告诉老杨**：成片位置、响度、问题帧、可疑句，请他听句尾、本质句语气和可疑句。**发布由老杨手动做。**

## 2. 本地构建检查（推分支前必做）

云端容器下载不了 Pexels，也没有配音凭证，所以用占位物测排版：

```bash
cd laoyang/knowledge-video
E=episodes/<期目录>
python3 $E/gen_lines.py                      # 在期目录里跑，生成 lines.json
mkdir -p $E/assets && ffmpeg -v error -y -f lavfi -i "color=c=0x302018:s=3008x2000" -frames:v 1 $E/assets/<bg文件名>.jpg   # 占位底图，尺寸写原图尺寸
python3 core/fake_vo.py $E                   # 静音占位配音；会把 dur 写进 lines.json
python3 core/build.py $E                     # 构建 + 各种体检
python3 core/qc.py $E                        # 抽帧，要求“帧问题： 0   控制台： 无”
# 看联系表：$E/build/qc_sheet.png
rm -rf $E/build $E/vo $E/assets && (cd $E && python3 gen_lines.py)   # 清理，并重新生成不带 dur 的 lines.json
```

**过关标准：** build 不报错（“提示”可以有，“未通过”不行）、qc 帧问题 0、联系表里卡片没有重叠或溢出。

## 3. 故障表（症状 → 原因 → 改法）

| 症状 | 原因 | 改法 |
|---|---|---|
| `anchor not found: vNN\|词\|s` | 卡片的 step 词不在那一句台词里。台词改了、卡片没同步最常见 | step 的词必须和台词逐字一致（去标点后）。**改任何台词，都同步搜一遍这句的 step** |
| `Cannot read properties of undefined (reading 'map')` | `bignum` 卡缺 `parts` | `bignum` 必须有 `parts`，哪怕只有一项 |
| 数字单位折行 | `unit` 太长（如“万亿元”） | 缩短单位，如“万亿” |
| 配音句尾体检未通过（尾字被切）：vNN | 服务端合成的那一遍句尾被切 | 改那一句的 `emo`（或台词）让缓存失效、重新合成，推新提交。配音缓存的键包含台词、emo、模型、语速、取样次数 |
| 封面报“主题词不在标题里” | 标题被 `<br>` 切开后，`cover.topic` 不是连续出现 | `cover.topic` 必须在标题去掉 `<br>` 后原样出现 |
| `publish.title 含视频号不允许的符号` | 标题里有逗号、顿号、句号 | 只允许《》“”：+？%，其余用空格 |
| `publish.tags 缺主标签 #民营企业` | 标签表没放主标签 | 第一个放 `#民营企业` |
| 留人套件体检：前 20% 有一段超过 7s 没变化 | 开头一句太长、卡片只有一个步骤 | 给那张卡加一个 step（同时加一个强调词），或换卡 |
| “缺底图，用占位色” | 本地没有底图文件 | 云端正常（Mac 会下载）；底图 URL 要用原图链接 |
| 底图分辨率不够 | 竖屏裁切后高度 <1962px | 换更大的原图 |
| 大文件传不到云端 | 文件传输接口对大文件会失败 | 在 Mac 上先用 ffmpeg 压小（封面转 720 宽 jpg，成片转 480p），再传 |
| Mac 上“连不上 GitHub” | 偶发网络问题 | 下一轮（5 分钟后）会自己重试，不用处理 |
| 提交后出片机没动 | 分支名或 `job.json` 位置不对 | 分支 `render/<期目录名>`，文件 `render-queue/job.json`，路径必须指向期目录 |

lint 硬规则（不过不让构建）：第 1 句 ≤30 字；有 `decision`；前 20% 画面间隔 ≤7s；第 1 张卡必须是 `hook`；封面主题词在标题里；发布标题符号；主标签。其余提示（钩子特征、预告答案、拉一把、平铺、感觉词）只是提醒，写稿时参考，不是都要消除；已确认的文案不为消提示而改。

## 4. 交接约定（git）

1. 在 `main` 上提交期目录（**不含** `render-queue/job.json`），推 `main`。
2. 建分支 `render/<期目录名>`，加 `render-queue/job.json`，提交，推分支，回到 `main`。
   ```json
   {"pipeline": "knowledge-video",
    "episode": "laoyang/knowledge-video/episodes/<期目录名>",
    "voice": "auto", "publish_mb": 120,
    "note": "写给 Mac 和老杨看的一两句：期号、句数、预计时长、底图、需要重点听哪里；人工发布，不要提交发布台"}
   ```
3. **重新出片 = 在分支上推一个新提交。** 修改先在 `main` 做，再在分支上 `git checkout main -- <期目录>` 并提交推送（这样 `job.json` 还在，期目录是最新的）。
4. 提交前 `build/`、`vo/`、`assets/` 要清掉（它们由 Mac 重新生成）。
5. 提交信息末尾带上本会话的署名行（按当前环境要求）。

出片结果在 Mac 的 `~/laoyang-render/待审/<期>/`：成片 mp4、`封面.png`、`联系表.jpg`、`出片报告.md`、`初筛.md`、`发布文案.md`。**先读 `初筛.md`**，里面有结论、响度、可疑句（“转写误差”多半是语音识别听错，不是配音读错；“不确定”要老杨听）。

## 5. 必须由老杨决定的事

- 文案确认（第 1 步）。
- 成片放行：他要听句尾、本质句语气和可疑句。
- 发布：自 2026-11-12 起全部**人工发布**，发布台里视频号、抖音·老杨魔方、抖音·屋顶机器人、小红书都已暂停。恢复自动发布要老杨明确说。
- 任何会改变他账号、凭证、设置的事。

## 6. 经验法则

- 先本地构建再推分支。一期里最费时间的失败都发生在“没本地跑就推”。
- 老杨的明确指令优先于标准（例如“不需要核实数据”“不注明出处”），但口径问题要如实提示。
- 事实只用有出处的；拿不准的引语宁可不用。
- 每期底图新选，不重复；不出现真人出镜；不画任何真实游戏的角色。
- 不确定时，在回复里说明你选了哪种理解，而不是问一串问题；会让他多花钱或不可撤销的事才先问。

## 7. 验收：空白会话测试

找一个没见过这个项目的 AI，只给仓库和一个选题，不给任何额外提示，让它做一期到“推渲染分支”为止。它卡住、问你的每一个问题，都是本手册漏掉的东西：补进本页，再换一个 AI 重测，直到它能自己走完。
