# 迭代制度：让这条管线每做一期就进步一点

目标：每一次用户反馈、每一期发布数据，都要么落到「这一期」，要么沉淀成「规则 / 效果 / 代码」，并且有自动测试保证进步不会把已有的东西改坏。

## 1. 三层，三种改法

| 层 | 文件 | 谁能改 | 改了要做什么 |
|---|---|---|---|
| 外壳与工具 | `core/` | 只在「通用」改进时改 | 跑 `core/regress.py`；版本号 +0.1（外框/版式变动 +1.0）；写 CHANGELOG |
| 规则与效果 | STANDARD.md、EFFECTS.md | 用户认可后改 | 写 CHANGELOG；同步技能（SKILL.md）和项目文档 |
| 每期内容 | `episodes/<期>/` | 每期自由改 | 写复盘 |

**向后兼容是硬规则**：新能力一律「默认关闭、按需打开」（例如 `SCENES.cN.free`、`HOOKS.texA`），规划院 V2.3 范例必须一直能原样渲染——回归测试就是在守这一条。

## 2. 每期闭环（Claude 每期必做）

1. **开工前读**：STANDARD.md、CHANGELOG 最近两版、BACKLOG 前 5 条、EFFECTS 里「标准」的效果。BACKLOG 里有适合本期题材的项目，主动提出「这期顺便试一下 X」。
2. **制作中记**：用户每一条修改意见原话记进 `episodes/<期>/复盘.md` 的「反馈」表。
3. **交付后分类**：每条反馈判一类——
   - **本期**：只跟这期内容有关（某句话改字、某个数字换来源）→ 改完即止。
   - **通用**：下一期也会遇到（「片尾 logo 太大」「文字出场太单一」）→ 必须沉淀，见第 3 节。
   - **偏好**：用户的审美倾向（「要更有张力」）→ 写进 STANDARD 的原则或 EFFECTS 的「性格」，并在 memory 里记一句。
4. **发布后回填数据**：48 小时和 7 天后，把播放、完播率、平均观看时长、点赞 / 评论 / 转发、掉人最多的秒数填进复盘「数据」表。掉人点对照时间轴，记下那一秒画面上是什么效果。

## 3. 一条「通用」反馈怎么沉淀

把一句反馈改写成**可检查的规则**，再决定落在哪：

| 反馈原话 | 改写成的规则 | 落点 |
|---|---|---|
| 片尾「老杨魔方」字太大 | 片尾 logo ≤84px、文字 44px、停留 ≤1.6s | shell.html + STANDARD §5.1 |
| 中间动画画布太小 / 头条太大 / 不要关注老杨魔方 | 头条 ≤78px；中间区放大到 x130–950 / y540–1380；全片不出现「关注老杨魔方」 | shell.html v2.1 + STANDARD §2.1、§5.1 |
| 画布上有一段空白、长时间没东西 | 中间区空白 ≤0.8 秒（收一拍除外），用挂在前半句的轻画面接住 | STANDARD §5.1、§8 + core/blankcheck.py |
| 不要巨大文字 | 单字高度 ≤96px，核心观点 64–88px | STANDARD §3 + qc 检查 |
| 文案去人名、公司名 | 画面和配音用「某专家 / 某上市公司」，FACTS.md 保留原始来源 | STANDARD §5.1 |
| 文字出现消失太单一 | 六种出场方式 + 8 条使用规范 | fx_text.js + STANDARD §5.2 |
| 要有疏密、快慢、色彩对比 | 三档速度、每章至少两档；同时只亮一种彩色；最重要的一句配最空的画面 | STANDARD §3、§5 |

能写成代码检查的就写进 `qc.py` / `regress.py`（例如越界、字号），让它以后自动拦住。

## 4. 效果的生命周期（EFFECTS.md 里的「状态」）

```
实验 ──用户看过演示并认可──▶ 候选 ──在一期正式发布中用过、没有负面反馈──▶ 标准
  ▲                                                                    │
  └──────── 连续两期被嫌弃 / 数据显示用到它的地方掉人明显 ◀──── 降级 / 退役 ┘
```
- 实验：只能在 `episodes/_demo_*` 里用。
- 候选：正式期可以用，但要在复盘里专门记一笔效果反馈。
- 标准：写进 STANDARD，技能默认会用。
- 每个效果在 EFFECTS.md 里记：位置、性格、**换场景怎么演**（同一个效果在别的题材里怎么重新演绎）、用过的期数。

## 5. 自动化

| 什么 | 什么时候 | 做什么 |
|---|---|---|
| `core/regress.py` | 改 core/ 后本地必跑；GitHub 上每个改到 `laoyang/knowledge-video/` 的 PR 自动跑 | 用占位底图 + 静音构建 4 个范例期，抽 37 帧和基准图逐像素比较，并检查越界和控制台报错。同一台机器结果完全一致，任何画面变化都会被发现 |
| `--update` | 有意改了画面 | 重生成基准图；必须在 CHANGELOG 写明改了什么、为什么 |
| `core/blankcheck.py` | 每期出片前 | 隐藏底图逐帧测中间区内容量，报出空白超过 0.8 秒的时段 |
| `core/qc.py` | 每期出片前 | 每秒一帧联系表、越界、字幕位置；`--video` 测响度和闪烁 |
| 阶段复盘 | 每做完 3 期 | Claude 汇总这 3 期的复盘和数据：哪些效果反复被夸 / 被改、掉人点集中在哪类画面 → 提出不超过 3 条升级（改规则、升降效果状态、新做一个效果小样）→ 开 PR 给用户确认 |
| 定期巡检（可选） | 每周一次的计划任务 | 读仓库里最新的复盘和 BACKLOG，没处理的通用反馈超过 2 周就提醒 |

## 6. 版本号与同步

- 版本写在 STANDARD.md 标题和 CHANGELOG.md；规则：外框 / 版式变动 +1.0，新效果 / 新规则 / 新工具 +0.1，修 bug 不升号只记一行。
- 每次升版本同步四处：**仓库**（PR 合并）、**技能**（SKILL.md 里的版本号和要点）、**视频工厂项目**里的「管线/知识分享版标准.md」、给用户的模板 zip（需要时）。
- 每期复盘的结论在项目 memory 里记一句用户原话层面的偏好，不记实现细节。
