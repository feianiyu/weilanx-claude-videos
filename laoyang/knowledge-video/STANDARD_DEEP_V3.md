# 老杨魔方 · 深度拆解版标准 v3（2026-11-10）

> 以后每一期深度知识视频都按这一份做。`lines.json` 写 `"v": 3` 就走 v3；旧期不受影响。
> v1（`STANDARD_DEEP.md`：选题测试、一手资料、问题链）和 v2（`STANDARD_DEEP_V2.md`：开场钩子、感觉词、留人套件、封面 v3、发布文案）里的规则继续有效，本文只写 v3 新增和改掉的部分，并在第 8 节给出一期从头到尾的步骤。
> 样片：`episodes/2026-11-10_AI时代企业管理_深度v3/`（EP.13 文案逐字不变，只换配音和画面）。

## 1. v3 改了什么

| 环节 | v2 的做法 | v3 的做法 | 为什么 |
|---|---|---|---|
| 配音模型 | 复刻音色默认的标准版 | 表现力增强版 `seed-tts-2.0-expressive` | 标准版不支持语气指令，v2 写的语气提示其实没有生效 |
| 配音单位 | 一句一配 | 仍然一句一配（老杨 11-10 试听三种配法后选的）；按「气口组」成段配留作可选 | 老杨听下来逐句的最像他 |
| 语气 | 一段通用提示 | 人设基调 + 每句的演法（`emo`） | 短关键词没用，要写「场景 + 怎么说」 |
| 上下文 | 无 | 全片共用一个会话 ID | 组与组之间语气也接得上 |
| 语速 | 配完用 ffmpeg 拉快 1.21 倍 | 模型里直接说快，`rate: 15`（约 1.15 倍） | 后期硬拉会让咬字发紧；老杨 11-10 要求在原语速上降 5% |
| 字的时间 | 按字数估，误差 0.1–0.2 秒 | 用接口返回的逐字时间戳 | 字幕、卡片动作和嘴对得更准 |
| 取样 | 配一遍就用 | 每句配 2 遍（开场 3 遍），自动剔掉坏的，取起伏最自然的 | 表现力版每次结果不一样，官方也说「可能需要抽卡」 |
| 人声后期 | 无 | 去低频轰隆、提清晰度、轻压缩、去齿音 | 更贴近近讲口播的听感 |
| 画面空间 | 重压暗的彩色底图 + 卡片 | 高清彩色底图降饱和、轻压暗 + 卡片；暖色烟带默认关 | 老杨 11-11：不要黄色颗粒，要照片清晰 |
| 画面构图 | 卡片内容顶对齐，中段常常空着 | 内容垂直居中，整卡放大 1.08 倍，关键数字加大 | 竖屏的视觉中心在中段 |
| 核心观点 | 都用卡片 | 每期 2–4 句用文字出场（`fxtext`：雾化、碎裂、粒子、水流、光扫、逐字） | 把以前的动画结合进来 |
| 开场和结尾 | 留人套件可选 | 默认用：第 1 张 `hook`，后段至少一张 `punch` | 流失集中在开场到片长 20% |

## 2. 文案：为嘴写稿

v1、v2 的内容纪律全部沿用：选题测试、一手资料、开场钩子和禁用清单、感觉词、口语化、决策桥接。v3 只加「写给配音」的三条。

### 2.1 每句标演法（`emo`）
配音只知道你写给它的东西。每句写一个 `emo`，可以用预设名，也可以直接写一句话。写的是「怎么说」，要具体到轻重和停顿。

| 预设 | 用在 | 演法 |
|---|---|---|
| `hook` | 开场第一句 | 突然问到痛处，带追问，不要铺垫腔 |
| `ask` | 提问 | 真的在问，说完像在等回答 |
| `num` | 关键数字 | 数字放慢、咬实，带一点意外，说完停半拍 |
| `turn` | 转折 | 前半句平着带过，转折词之后压低放慢 |
| `fact` | 交代来源 | 平实、稍快，像随口告诉朋友 |
| `story` | 讲故事 | 娓娓道来，有画面感 |
| `aha` | 点破 | 恍然大悟，干脆 |
| `heavy` | 大实话 | 一句一顿，越说越重 |
| `list` | 分条 | 一条一条数，每条开头咬实 |
| `warm` | 过渡 | 亲切放松，带一点笑意 |
| `close` | 收尾 | 放慢，沉下来，说完留白 |
| `invite` | 评论区提问 | 轻松真诚，像聊完顺口问一句 |

自己写时照这个样子写：`"前半句轻松带过；“可”字一转，压低放慢，说到“只有百分之三十七”时带着意外"`。只写「开心」「严肃」这类词基本没有效果。

- 一期里相邻三句不要用同一个 `emo`，否则听起来又是一个调子。
- 全片人设基调写在 `voice.context`，不写就用默认的（做了二十年咨询的顾问，茶桌对面聊天）。

### 2.2 气口组（`g`，可选，默认不用）
默认逐句配音，这一节只在 `voice.group` 写 `"breath"` 时生效。
- 意思连着、应该一口气说下来的 2–3 句写同一个 `g`（一个数字，相邻句相同即同组）。例：提问 + 追问；事实 + 转折；三条并列。
- 一组不超过 3 句、85 字。组太长，后半段的情绪会变平。
- 金句、点破的那一句单独成组，前后会自然留出停顿。
- 不写 `g` 时自动分：同一章节里相邻的句子按上面的上限合并。
- 组内句与句的停顿由配音自己决定，时间轴照着排；组与组之间用 `gapSec`（默认 0.25–0.3 秒），章节之间用 `secGap`。

### 2.3 长度
- 目标 90–150 秒（约 500–800 字）。视频号数据：超过 120 秒的 15 条，片长 20% 处只剩 6.2%，是全账号最差的一组。
- 超过 150 秒的题目，先问能不能拆成上下两期。真要做长，每 20–30 秒要有一句新的感觉句或一张 `punch`。
- 这条是建议，不拦出片。

## 3. 配音 v3

### 3.1 lines.json 写法
```json
"voice": {"engine": "volc", "v": 3, "model": "expressive", "rate": 15, "takes": 2},
"lines": {
  "v01": {"sec": "c0", "sub": "你们公司，是不是也给员工都开了AI账号？", "emo": "hook"},
  "v02": {"sec": "c0", "sub": "使用了AI以后，企业是否降低了成本，或者提高了收益呢？", "emo": "ask"}
}
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `voice.v` | — | 写 3 才走 v3 |
| `voice.model` | `expressive` | 表现力增强版；`standard` 是标准版（不认语气提示） |
| `voice.rate` | 15 | 模型内语速，-50 到 100，100 是 2 倍速。15 约等于 1.15 倍 |
| `voice.group` | `line` | `line` 逐句配；`breath` 按气口组配（见 2.2） |
| `voice.takes` | 2 | 每句配几遍；`hook` 那句自动多配一遍 |
| `voice.pick` | 起伏最自然 | 写 `"first"` 就只取第一遍 |
| `voice.context` | 内置人设 | 全片基调；写空字符串就不带语气提示 |
| `lines[k].emo` | 无 | 这一句的演法，见 2.1 |
| `lines[k].g` | 无 | 气口组，只在 `group: breath` 时用 |
| `lines[k].tts` | 同 `sub` | 念法和字幕不同时写（多音字、专有名词） |

### 3.2 一遍配音怎么算「能用」
每遍先过三项体检，不过的直接丢：
1. 不漏字：返回的逐字时间戳覆盖 85% 以上的字。
2. 语速不离谱：3.6–9 字/秒。
3. 中途不卡：字与字之间没有超过 1.6 秒的停顿。

通过的几遍再用本机 whisper 听写回文字，和台词比对，只留念得最准的（相似度与最高的差 0.03 以内）。
剩下的里面，取「起伏分」最高的：音高标准差（半音）+ 6 × 字长变化系数。每组取了第几遍、分数多少，记在 `vo/_takes.json`，出片报告有一行汇总。
起伏分只是帮忙挑，不能代替耳朵：数据上分不出「自然」和「不自然」，最后要老杨听。

### 3.3 缓存和花费
- 缓存按组算：组里任何一句的字、语气、参数变了，整组重配。换了复刻音色，缓存自动作废。
- 语气提示不计费；每多配一遍，按那一组的字数多收一次。一期 800 字、配 2 遍，约 1700 字的量。

### 3.4 复刻音色本身
接口只能在复刻样本的基础上发挥。如果录样本时是平着念稿，配出来的底子就是平的。
想再上一个台阶：重新录一段 20–30 秒的样本，内容就用一期口播的开场，按平时跟老板聊天的状态说（有问句、有转折、有重音），环境安静、不要配乐。录完换 `VOLC_SPEAKER_ID` 即可，管线不用改。

### 3.5 配音实验台
想比较不同配法时：把实验说明放进 Mac 的 `~/laoyang-render/inbox/<名字>.json`（`{"kind": "voice-lab", "spec": {...}}`，格式见 `core/voice_lab.py`），出片机下一轮会跑，结果在 `~/laoyang-render/lab/<名字>/`。不经过 GitHub。

## 4. 画面 v3

### 4.1 底图和层次（2026-11-11 改）
老杨 11-11：不要黄色颗粒，保留照片清晰度；底图用**彩色照片降饱和**（保留一点原色，不是纯黑白）。所以 v3 默认：
1. **底图**：高清实景图，**饱和度降到约四成**、略提对比，**轻压暗**（顶部标题区和底部字幕区压得深，中段卡片区约五成，照片细节保留）。不加胶片颗粒。`"look": "mono"` 是纯黑白，`"look": "dark"` 退回 v2 的重压暗彩色。
2. **卡片**：内容垂直居中，整卡放大 1.08 倍；大数字 210px。橙色只留给强调字和数据。
3. **文字出场**（`fxtext`）照用。暖色烟带和微尘**默认关**；个别题材想要，写 `"fx": {"mist": 0.6}`。

底图要求不变：原图竖向可见高度 ≥ 1962px；降饱和之后主要看明暗和线条，选图优先**有纵深、有线条、明暗分明**的（厂房、走廊、楼梯、城市俯瞰），避免大面积纯色和人脸特写。

### 4.2 每期的画面骨架
| 位置 | 用什么 | 要求 |
|---|---|---|
| 第 1 张 | `hook` 钩子大字卡 | 每行不超过 8 个字（字才够大），一行一个锚点，跟着嘴砸出来 |
| 抛出本期问题 | `fxtext` | 一句话，碎裂或雾化出场 |
| 证据段 | `bars` / `bignum` / `duo` / `line` / `quote` 等 | 每张卡至少 2 个步骤，跟着嘴一步步长出来 |
| 每个段落的结论 | `punch` 或 `fxtext` | 全片 2–4 张，不要每段都用 |
| 桥接段 | `focus` / `check` | 沿用 v2 |
| 结尾 | `question`（评论区问题） | 沿用 v2 |

- `fx.hits` 写 3–5 个：数字落下、转折词、结论的那个词。
- 锚点不要用阿拉伯数字（念法转换后可能对不上），用数字旁边的词。
- 开场到片长 20%，画面每 5–7 秒必须变一次（`"retain": {"maxGap": 7}`，不满足不让出片）。

### 4.3 文字出场怎么选（`fxtext`）
| 出场 | 性格 | 用在 |
|---|---|---|
| 雾化 | 轻、带悬念 | 抛问题、过渡 |
| 碎裂 | 冲、有力 | 推翻常识、反问 |
| 粒子 | 聚拢、成形 | 结论成形 |
| 水流 | 顺、缓 | 讲故事、历史 |
| 光扫 | 亮、确定 | 定论 |
| 逐字 | 稳 | 引用原话 |

一期最多用 3 种，同一种不要连着用。每行不超过 12 个字，最多 3 行，`cy` 在 560–1400 之间。

### 4.x 视频号安全区（2026-11-11，硬规则）
- 视频号在高屏手机上按**高度铺满**播放，1080 宽的画面左右各被裁掉约 45px（EP.15 手机实测：卡片文字贴到手机边沿）。
- **所有文字、方框、结构图必须在 x104–976 内**（左右各留 104px，约 60px 余量给不同机型）。外框已按此改（`shell_deep.html`），舞台模式整卡缩放上限 0.94（`cards.js` 的 `SAFE_Z`），不要再放大到 1.0 以上。
- 质检（`_checks.py`）会报「越界(出卡片区)」和「视频号安全区」；背景照片、烟雾等装饰不受限，可以铺满。
- 全屏文字卡（`fxtext`）、自己写的画面元素，也要按这条留边。

## 5. 声音

- **人声后期**（v3 配音自动开）：80Hz 高通、250Hz 略减、3.6kHz 和 9kHz 略提、3:1 轻压缩、去齿音。只处理人声。
- **配乐**：默认还是程序合成的和声垫底，比人声低 19dB 左右（`bgmUnder`）。深度版不卡拍。
- **音效**：默认不加。要加时只在 `hook` 第一行、`punch` 落下这两处，用 `sfx` 字段，音量比人声低 16dB 以上。
- 成片响度 -14 LUFS，真峰值不高于 -1 dBFS（出片机自动检查）。

沿用 v2：封面模板 v3（§5.4）、封面标题规则（直接点出这期讨论什么）、发布文案（§2.6.4–5：短标题、描述第一行照抄开口句、标签）。

## 7. 质检

| 项目 | 谁做 | 标准 |
|---|---|---|
| 开场话术体检 | `lint_opening.py`，构建时自动 | 禁用清单、感觉词、决策桥接 |
| 留人体检 | 构建时自动 | 第 1 张是 `hook`；前 20% 画面间隔不超过上限 |
| 配音体检 | 配音时自动 | 3.2 的三项；有组没通过，报告会点名 |
| 念错字抽查 | 出片机 whisper | 报告里列出要听的句子（同音字会误报，听一下就行） |
| 越界、字幕、亮度、响度 | 出片机自动 | 同 v2 |
| 听感 | 老杨 | 重点听开场、数字句、转折句、结尾 |

听感不满意时，改那一句的 `emo`（写得更具体），或者把它和前后句的 `g` 调一下，重新推分支。只有改过的组会重配。

## 8. 一期从头到尾

1. 选题过选题测试，查一手资料，写 `FACTS.md`、`PLAN.md`。
2. 写稿（v2 的开场和口语规则），老杨确认文案。确认后不再改字。
3. 给每句标 `emo`，划 `g`；定卡片（按 4.2 的骨架），写 `fx.hits`。
4. 本地用占位配音构建、抽帧看画面：`python3 core/fake_vo.py <期>` → `python3 core/build.py <期>` → `python3 core/render.py <期> snap <秒…>`。
5. 推 `render/<期>` 分支（带 `render-queue/job.json`）。Mac 出片机自动配音、渲染、质检、出封面。
6. 看出片报告和联系表；老杨听配音。有问题改 `emo` / `g` / 卡片后重推。
7. 通过后进发布台。发布 48 小时回填「3 秒划走」「20% 处留存」「转发率」。

## 4.y 配音句尾不许吃字（2026-11-12）
- 切句不能信服务端的「字结束时间」（偏早 0.2–0.65s）。必须用 `speech_end()` 看真实波形，等声音真正静下来再切。
- `build.py` 自动跑 `check_vo_tail.py`：每句最后 50ms 不静音即失败。失败后只重配报出的句子，不要放行。
- 听配音时重点听句尾的字，尤其是句末是数字、单字名词（“元”“种”“管”）的句子。

## 4.z 底图不许跨期复用（2026-11-12，老杨要求）
- 每一期必须换一张新的高质量底图，不能沿用上一期。选图前在 Pexels 页面核对：摄影师、原图尺寸（竖屏裁切后高度 ≥1962px）、免费商用许可、画面里没有人脸和品牌标识。
- 横图也可以用（居中裁切），`lines.json` 的 `bgs.note` 写明编号、标题、摄影师、尺寸、许可。
