# 老杨魔方 · 深度拆解版 v5「逻辑图谱版」（2026-11-12）

> v5 在 v4 上加两件事：**13 种新逻辑图**（`core/cards_logic.js`），和一个**「这段话是什么逻辑关系 → 用哪种图」的识别表**。
> 配音、字幕、底图、留人套件、封面、发布规则沿用 v3；`map` / `stack` 沿用 v4。
> 演示期：`episodes/_demo_v5_逻辑图谱/`（13 种图各演一遍，数字是示意）。
> 新一期写 `"layout": "v5"`：build 会跑画面多样性体检（§5），不过不让出片。

## 0. 为什么要 v5

2026-11-12 统计最近 8 期：5 期的文字卡（text / punch / question / shift / list）占 60%–83%，逻辑图只用了 0–2 种（几乎只有 `chain` 和 `map`）。
结果是每期看起来都一样：一张字卡接一张字卡。老杨的要求：**按内容的逻辑关系选图，用更丰富的结构图表现数据和逻辑**。

## 1. 写画面前先做一步：给每一段标「内容关系」，再决定用知识卡还是逻辑图

**没有固定模板。** 知识卡（大数字、原文、故事、清单、金句）和逻辑图（飞轮、漏斗、冰山……）是并列的两套工具，按这一段的内容挑：
- 这一段在**摆事实**（一个数、一句原文、一个故事、几个发现）→ 知识卡更直接；
- 这一段在**讲关系**（谁导致谁、怎么构成、怎么筛、怎么变、两边怎么拉扯）→ 逻辑图。

做法：文案确认后，逐段问一句「这段讲的是什么？」，把答案写进卡片的 `rel` 字段（取值见 `core/lint_visual.py` 的 `REL` 表，§2 是它的人话版）。
`rel` 定了，候选卡就定了；从候选里挑**和前后两张不一样**的那个。
所以讲历史、讲人物的一期，知识卡自然多；讲机制、讲账的一期，逻辑图自然多——比例由内容决定，体检只看「对不对」和「单不单调」。

## 2. 识别表：逻辑关系 → 图

| 这段在讲 | 口播里的信号词 | 用 | 卡片 |
|---|---|---|---|
| **循环 / 正反馈** | 越…越…、飞轮、滚雪球、恶性循环 | 飞轮，光点绕圈；断了就打 ×，光点堵在断点 | `cycle`（`bad:true` 红色恶性循环） |
| **一件事拆成几块** | 拆开看、分三件事、原因有三 | 拆解树，根 → 枝 → 叶 | `tree` |
| **层层筛选、转化** | 一百个里…最后只剩、转化率、过五关 | 漏斗，一层层变窄 | `funnel` |
| **比例感（几个里有几个）** | 每 100 个里、十家有三家、三分之一 | 单位图，点一颗颗亮 | `dots` |
| **底座和上层（依赖）** | 基础、底层、往上才是、地基 | 金字塔，从底往上垒 | `pyramid` |
| **按时间走的阶段** | 先…再…然后、某年、阶段、历程 | 竖时间轴，标「卡在这」 | `timeline` |
| **能力 / 等级的跃迁** | 台阶、升级、从 A 到 B 到 C、第几级 | 阶梯，从左下往右上长 | `ladder` |
| **几个条件同时满足** | 同时、既要又要、交集、重合 | 韦恩图，交集填橙 | `venn` |
| **总量分去了哪里** | 一百块里…分给、流向、拿走了 | 分流（桑基），带子宽度按比例，光点往下流 | `sankey` |
| **一个整体的构成** | 占了一半、构成、大头是 | 构成环，一段段画出来 | `donut` |
| **表象和本质** | 表面上、真正的原因、水面下、看不见的 | 冰山，水上一角、水下大块 | `iceberg` |
| **规则 / 模式换了** | 以前…现在、过去…今后、旧…新 | 新旧对照，左灰右橙 | `versus` |
| **两股力量拉扯** | 一边…一边、推力、阻力、拦着 | 力场，橙箭头推、红箭头挡，中线往净方向挪 | `forces` |
| 两种选择掂量 | 值不值、划不划算、两害相权 | 天平 | `balance`（v2） |
| 两个维度给东西分类 | 高…低…、四种情况、象限 | 四象限 | `matrix`（v2） |
| 一笔账从 A 变 B | 利润怎么没的、一加一减 | 瀑布 | `waterfall`（v2） |
| 趋势 | 涨了、跌了、一路、拐点 | 折线 | `line`（v2） |
| 传导链 | A 导致 B、于是、传到 | 因果链 / 结构图 | `chain`（v2） / `map`（v4） |
| 组织、关系网、谁连谁 | 上下级、部门、谁管谁 | 结构图 | `map`（v4） |
| 层级压缩 | 14 层压到 5 层 | 层级柱 | `stack`（v4） |
| 一个反常数字 | 惊人的数 | 大数字 | `bignum` |
| 金句、开场钩子、评论区 | — | 文字卡 | `hook` / `punch` / `question`（各期最多 3 张） |

**判不准时**：先问「观众看完这张图，能不能不听声音也复述出关系？」能，就是对的图。

## 3. 13 种新卡的数据格式

通用：`s` = 第几个 step 出现；`hot` = 从第几个 step 起变橙；`dim` = 从第几个 step 起变暗；文字里 `*词*` 橙色、`|` 换行；字号自动缩到放得下。

```jsonc
// cycle 飞轮 / 循环（3–6 个节点）
{"title":"…","items":[{"t":"产品好","s":1},{"t":"再投入","n":"研发 · 人才","s":4}],
 "center":{"t":"越转|越快","s":5},"flow":{"s":5},"break":{"i":2,"s":6,"label":"利润被抽走"},"bad":false}
// tree 拆解树（最多 3 枝 × 3 叶）
{"root":{"t":"老板越来越累"},"kids":[{"t":"决策太多","s":1,"hot":3,"kids":[{"t":"事事要拍板"}]}]}
// funnel 漏斗（v 只管宽度；rate 写在两层之间）
{"levels":[{"t":"想法","val":"100","v":100},{"t":"立项","val":"30","v":30,"s":1,"rate":"剩 30%"}],"note":{"t":"…","s":3}}
// dots 单位图（默认 100 个点，10 列）
{"total":100,"on":5,"s":1,"label":"真正落地","red":{"n":10,"s":2,"label":"做砸的"}}
// pyramid 金字塔（levels[0] 是塔尖；s 自己写成从底往上）
{"levels":[{"t":"战略","n":"往哪走","s":3,"hot":3},{"t":"组织","s":2},{"t":"流程","s":1}]}
// timeline 竖时间轴（≤6 项）
{"items":[{"d":"2019","t":"靠机会","n":"小字","s":1,"dim":4}],"now":{"i":1,"s":4,"label":"多数卡这"}}
// ladder 阶梯（3–5 级）
{"steps":[{"t":"一个人干","n":"老板是发动机","s":1}],"now":{"i":0,"s":4,"label":"你在这"}}
// venn 交集（2 或 3 个圈）
{"sets":[{"t":"客户要"},{"t":"你能做","s":1},{"t":"还赚钱","s":2}],"mid":{"t":"主航道","s":3}}
// sankey 分流（注意总量叫 from，不能叫 src——src 是出处行）
{"from":{"t":"收入","val":"100"},"outs":[{"t":"成本","val":"60","v":60,"s":1},{"t":"到手","val":"15","v":15,"s":4,"hot":4}],"unit":"单位：元"}
// donut 构成环（≤6 段）
{"center":{"num":20,"unit":"块","label":"费用合计"},"parts":[{"t":"销售","val":"11","v":11,"s":1,"hot":2}]}
// iceberg 冰山
{"above":[{"t":"利润下滑"}],"deepS":1,"below":[{"t":"定价权","s":2},{"t":"组织效率","s":4,"hot":4}],"wl":"水面上：…","bl":"水面下：…"}
// versus 新旧对照（≤5 行，每格 ≤10 字）
{"left":"以前","right":"现在","rows":[{"a":"靠关系拿单","b":"靠产品拿单","s":1}],"verdict":{"t":"…","s":3}}
// forces 力场（w 1–5 决定箭头长短）
{"center":"公司","push":[{"t":"客户在变","w":4,"s":1}],"pull":[{"t":"老习惯","w":2,"s":3}],"net":{"dir":1,"s":5,"t":"推力更大：*变是迟早的事*"}}
```

## 4. 画面原则（在 v4 的 6 条上加 4 条）

1. **一期一张主图 + 至少 3 种副图**：主图贯穿（v4 原则），副图按 §2 换着用，不让两张相邻的卡长得一样。
2. **图跟着嘴长**：每张逻辑图至少 2 个 step；一张图不说完就不换（一张图通常 5–12 秒）。
3. **讲到哪亮哪**：每张图最后一步，用 `hot` 把结论落到一个元素上（变橙），用 `dim` 把讲完的压暗。
4. **数据要「看得出比例」**：有数字时优先用能显示比例的图（漏斗、单位图、分流、构成环、瀑布），不要只把数字写大。示意数字在 eyebrow 写「示意数据」。
5. 同一种文字卡（punch / question / text / shift / list / quote）≤ 3 张；同一种卡不连排 3 张；全期 ≥ 5 种不同画面。
6. **每期不一样**：主图类型不和上一期重复（`map` 除外）；卡片顺序和上一期相似度 > 60% 会提示。

## 5. 画面多样性体检（`core/lint_visual.py`）

build 对 v≥3 的深度版自动跑；`"layout": "v5"` 时前两类**不过不让构建**，第三类只提示：
1. **对不对**：每张卡（hook 除外）都写了 `rel`；卡片类型在这个 `rel` 的候选里。
2. **单不单调**：同一种卡不连排 3 张（`map` 除外）；同一种文字卡 ≤ 3 张；全期 ≥ 5 种画面。
3. **和上一期撞不撞脸**：主图类型相同、或卡片顺序相似度 > 60% 时提示。
文字卡占比、逻辑图种数只报告，不设门槛。

## 6. 一期的骨架（v5）

| 位置 | 用什么 |
|---|---|
| 0–5 秒 | `hook` |
| 证据 | 能显示比例的图：`dots` / `funnel` / `donut` / `sankey` / `waterfall` / `bars` |
| 机制 | 主图：`map` / `cycle` / `tree` |
| 转折、本质 | `iceberg` / `versus` / `forces` / `balance` |
| 路径、怎么办 | `timeline` / `ladder` / `pyramid` / `matrix` |
| 金句 | `punch` |
| 结尾 | 回到主图全景 + 评论区问题 |
